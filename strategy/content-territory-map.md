# NYF Holdings — Searchable Content Territory Map

**Status:** Working production map  
**Rule:** Retrieval before reconstruction. Substance before discovery.  
**Purpose:** Turn the existing NYF corpus into a set of coherent, searchable publishing territories without collapsing distinct bodies of work into one generic blog.

## 1. What this map is for

NYF already contains multiple bodies of work: editorial synthesis, documentary writing, financial-system research, tax and accounting investigations, application concepts, long-form manuscripts, infrastructure research, and operating records.

The publishing problem is therefore not "generate more content." It is:

1. retrieve what already exists;
2. identify the subject territory each piece occupies;
3. preserve provenance and project lineage;
4. group related material into durable editorial verticals;
5. publish only when a vertical has enough substance to deserve a public surface;
6. measure search demand and audience response before scaling.

A future network of niche publications should be built from this map rather than from mass-produced thin pages.

## 4. The niche-site rule

Do **not** create a site because a keyword has traffic.

A new niche publication should pass all five gates:

1. **Corpus gate** — at least 8–12 substantive source items or one deep manuscript/research body.
2. **Authority gate** — NYF has an identifiable point of view or primary-source advantage.
3. **Retrieval gate** — prior work has been inventoried so new writing does not duplicate forgotten work.
4. **Editorial gate** — pages answer real questions and can stand independently of monetization.
5. **Measurement gate** — the first publishing surface demonstrates impressions, engagement or referral demand before replication.

The preferred sequence is **one strong vertical → measure → refine → replicate**, not hundreds of thin WordPress properties.

## 5. Retrieval schema

Every recovered item should eventually be represented with these fields:

- `id`
- `working_title`
- `source_system` — GitHub / Drive / ChatGPT / Claude / Gmail / local archive / other
- `source_locator`
- `created_at` / approximate period
- `project_family`
- `subject_territories[]`
- `artifact_type` — manuscript / dissertation / note / synthesis / research / app spec / code / source evidence / publication
- `status` — fragment / draft / complete / published / superseded / unknown
- `publicability` — public / private / review-required / unknown
- `provenance_notes`
- `feeds_into[]`
- `derived_from[]`
- `search_questions[]`
- `keywords[]`
- `retrieval_confidence`

This is lineage mapping, not merely file cataloguing.

## 8. Monetization is downstream of usefulness

Potential monetization can include display advertising, sponsorship, affiliate relationships, subscriptions, licensing, products or services. None of those should determine what gets invented.

The corpus determines what NYF can credibly publish. Search data determines where people are looking. Audience behavior determines what deserves scaling. Monetization comes after those three signals align.

---

## 9. Immediate production decision

For now, **do not spin up a farm of niche WordPress sites**.

Use `nyfholdings.ca` as the live testing surface while the corpus is retrieved and classified. Build depth inside the existing verticals. Once one subject territory demonstrates both source depth and external demand, it can graduate into a dedicated publication or domain with its own editorial identity.

This map should evolve as retrieval continues; unknown relationships remain unknown until source material supports them.
